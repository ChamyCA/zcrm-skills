If you have…Run

A prospect who has not told you their needs in CRM terms/ZCRM-discovery
Discovery material or a customer brief, ready to design from/ZCRM-design

A need to check that the skills and a prospect's outputs agree/ZCRM-alignment

Get started

You need Claude Code, uv, Node.js 20+, and a demo or sandbox Zoho org. Your admin gives you the install line.

1. Install

  1. Open a terminal in your project folder.
  2. Paste this:
uvx --from git+ssh://git@<host>/<owner>/zcrm-skills.git zoho-skills init --here
  1. Wait for the green "Next Steps" box.
  1. Open a terminal in your project folder.
  2. Paste this:
uvx --from ./zoho_skills_cli-<version>-py3-none-any.whl zoho-skills init --here
  1. Wait for the green "Next Steps" box.

Add --dry-run to preview without changing anything.

2. Check

./zcrm-exec doctor

Look for PASS Agent protections configured. FAIL? See "If something goes wrong" below.

3. Add your tokens

  1. Create a Self Client in the Zoho API console.
  2. Run the scopes command and paste the result into it.
  3. Run the auth command in your own terminal, not the chat.
  4. Answer the hidden prompts: client ID, client secret, grant code.
./zcrm-exec scopes --profile discover
./zcrm-exec auth init --profile discover --dc US
Type tokens only in your own terminal. Never paste them in the chat. If you did, revoke them in the Zoho API console.

After the plan check, run ./zcrm-exec scopes --profile build --plan <your plan file>, then repeat both steps with --profile build. When done, revoke both:

./zcrm-exec auth revoke --profile build
./zcrm-exec auth revoke --profile discover

4. Build

Open Claude Code in the folder. Type /ZCRM-intake (or /ZCRM-discovery), then follow the chain.

intake → design → planner → executor → demo

The executor is beta. Start with one small step in a sandbox org. It shows each step and waits for your yes. It never deletes.

Install options

OptionWhat it does
--dry-runPreview changes, write nothing.
--no-executorSkills only, no executor.
--forceOverwrite skills, fix unsafe settings.
--include-alignmentAlso install the audit skill.

Update

Run the same install command again with --force. Executor files refresh with or without it.

If something goes wrong

ProblemFix
zcrm-exec not foundRun ./zcrm-exec from the project folder.
Install stopped with exit code 2A setting of yours is unsafe. Fix it, or use --force.
Node missing or older than 20Install current Node LTS, then open a new terminal.
Doctor shows FAILFix Node or re-run the install, then run doctor again.
Build auth refusedConfirm the plan check in chat first, then retry.
Grant code expiredCreate a new grant code and run the auth command again.

How the skills connect

Each skill writes files under output/<prospect-slug>/ that the next skill reads. The skills are independent entry points, not mandatory phases.

The 7 skills

Invoke any skill by typing its name in Claude Code, followed by what you want. Every skill asks questions as multiple choice by default and assumes Zoho CRM Enterprise unless you say otherwise (all except ZCRM-alignment).

ZCRM-intake Available

Purpose
A guided front door. It asks for the prospect name and discovery material, then hands everything to design. It does no design itself.
When to use
You want to design a CRM for a prospect but have not organized your discovery material yet, for example "I have a call transcript for Acme".
Inputs
  • Prospect name
  • At least one of: call transcript or notes, an email, a requirements document, website excerpt
Outputs
Your material, passed unchanged to ZCRM-design. It then relays in plain language what the design skill produced or still needs.
Invoke
/ZCRM-intake I have a call transcript for Acme Logistics
Next step
ZCRM-design
Source
.claude/skills/ZCRM-intake/SKILL.md

ZCRM-discovery Available

Purpose
Interviews a prospect who is new to CRM, one plain-business-language question at a time, and turns the answers into a structured brief. Every answer is tagged with where it came from. It will not stop until it has asked about the prospect's industry and their biggest pains.
When to use
You want to run or continue a discovery interview, or customer-brief.md needs to be created or updated.
Inputs
  • Prospect name (used for the output folder)
  • The prospect's answers, collected across sessions you can pause and resume
  • Optional: website or documents, which are presented back for the prospect to confirm
Outputs
output/<prospect-slug>/customer-brief.md, plus a session-state file that lets the interview resume. The brief carries Industry: and Pain: markers.
Invoke
/ZCRM-discovery Start a discovery interview for Acme Logistics
Next step
ZCRM-design and ZCRM-demo use the brief
Source
.claude/skills/ZCRM-discovery/SKILL.md

ZCRM-design Available

Purpose
Turns discovery material into a traceable, validated Zoho CRM design package: data model, pipelines, blueprints, automation, and persona dashboards. Each element cites the requirement behind it.
When to use
You are designing a CRM solution for a specific prospect, before any demo org is built.
Inputs
  • Discovery material: calls, notes, emails, documents, website, web research
  • Blocking inputs (industry, top pains, sales process); the skill asks if they are missing
Outputs
A numbered set of documents in output/<prospect-slug>/, ending with 12-handoff-spec.yaml. It never writes to a live CRM org.
Invoke
/ZCRM-design Design the CRM for Acme Logistics
Next step
ZCRM-planner
Source
.claude/skills/ZCRM-design/SKILL.md

ZCRM-planner Available

Purpose
Turns a validated design package into one credential-free, dependency-ordered plan for building it with the Zoho CRM API. The plan is discovery-first and requires explicit confirmation before each write.
When to use
You have a validated design package and want a plan to build it in a real demo org.
Inputs
output/<prospect-slug>/12-handoff-spec.yaml. The skill refuses to continue unless its validation shows zero blocking failures.
Outputs
output/<prospect-slug>/14-implementation-plan.md. The skill never calls Zoho itself.
Invoke
/ZCRM-planner Generate the implementation plan for acme-logistics
Next step
ZCRM-executor, then ZCRM-demo
Source
.claude/skills/ZCRM-planner/SKILL.md

ZCRM-executor Beta

Purpose
Builds a validated plan in an approved demo or sandbox org one chat-confirmed step at a time. It acts as a senior Zoho API engineer: it composes each call from the plan and the Zoho documentation, shows you the exact request, and runs it only after you confirm in chat. Credentials never enter the conversation.
When to use
You have a validated plan and want it built, resumed, verified, or reported on in a demo or sandbox org.
Inputs
  • 14-implementation-plan.md and 12-handoff-spec.yaml
  • An approved target org definition
  • Credentials that you load yourself in your own terminal
Outputs
Written by report generation under output/<prospect-slug>/: run-ledger.jsonl, execution-report.md, manual-steps-checklist.md, api-upgrade-proposals.md, rollback-checklist.md.
Invoke
/ZCRM-executor status to check readiness, or give a prospect slug.
Next step
ZCRM-demo
Source
.claude/skills/ZCRM-executor/SKILL.md, specs/007-crm-build-executor/tasks.md
What works today. Plan intake, the target-org guard, credential setup (auth init, doctor, scope listing), read-only discovery with a reconciliation report you confirm, the guarded write path (preview, execute, verify, skip), manual-step recording, API upgrade proposals, and report generation.
Not built yet. Live validation. Nothing has run against a live org yet; everything is tested on a mock server only. For the first live run, build one small step in a sandbox org.
Safety rules. You confirm each write in chat against the exact preview and request hash. That confirmation is prompt-level, not terminal-enforced, and is accepted only for internal demo or sandbox orgs. The code enforces the target-org and scope guards, the request-hash match, a read-back check, and a secret-free log. You enter tokens in your own terminal, never in chat. There is no delete tool; rollback is a manual checklist. Sample-data seeding is out of scope in this version.

ZCRM-demo Available

Purpose
Builds a truthful, prospect-specific demo package. Each scene links a real customer pain to a real org capability, a real screen, and a business outcome. It produces a draft for you to review; you deliver it.
When to use
You want a demo plan or script for a specific prospect, against a demo org you have already built.
Inputs
  • Customer brief
  • Customer detailed pain case
  • Read access to the Zoho CRM demo org through the Zoho CRM MCP tools
Outputs
In output/<prospect-slug>/: org-model.md, org-snapshot.json, customer-profile.md, coverage-matrix.md, demo-plan.md and .html, demo-script.md, gaps-and-risks.md, summary.md.
Invoke
/ZCRM-demo Build the demo plan for Acme Logistics
Next step
You review and deliver the demo. The skill never presents to a prospect.

ZCRM-alignment Available

Purpose
Audits the skill chain and a prospect's outputs for gaps between what each skill promises and does. It flags gaps by severity and fixes the safe ones.
When to use
You want to check, align, or fix gaps across the skills, their handoffs, or a prospect's output folder. Run it at any point.
Inputs
Optional: a skill name, a prospect slug (output/slug), or report-only.
Outputs
A report with findings by severity, fixes applied, decisions needed, and chain health. With report-only it edits nothing; otherwise it asks before any contract or prospect-content change.
Invoke
/ZCRM-alignment report-only or /ZCRM-alignment acme-logistics
Next step
None. It audits the other skills.
Source
.claude/skills/ZCRM-alignment/SKILL.md

How the skills get better

At the end of a build, each skill writes anonymized lessons to its file in lessons/. A maintainer reviews them with /ZCRM-alignment lessons before anything changes.

FAQ

What does it cost?

Pricing and licensing are not covered on this page. Claude Code usage follows your team's plan, so check with your administrator. [HUMAN REVIEW]

What data can the skills access?

They read what you give them (transcripts, notes, documents) and the files they wrote earlier. ZCRM-demo and the executor can read a Zoho CRM demo org through the connected tools. Use demo or sandbox orgs only, and never copy Corp data into them.

Where are the outputs saved?

In output/<prospect-slug>/ in your project. The folder is git-ignored, so prospect material stays out of the repository.

Will a skill change my live CRM?

Only the executor can write, and only to an approved demo or sandbox org, one step at a time, after you confirm that exact step in chat. The confirmation is prompt-level, and the executor is beta: it has not yet run against a live org. Intake, discovery, design, planner, and alignment never call Zoho to write. ZCRM-demo is read-only by default and needs your explicit "yes" for any specific write.

What if the output looks wrong?

Run /ZCRM-alignment report-only to look for gaps between the skills and the files. Check the source tags on claims: facts are tagged by origin, and anything unverified is labeled. Do not present unverified, commercial, or competitor claims to a prospect.

Do the skills ever see my credentials?

No, credentials stay in your terminal, never the chat. If one appears there, revoke it.

What are the lessons files?

Every skill ends with a "Capture lessons (close-out)" step that writes anonymized lessons to lessons/<skill>.md. Run /ZCRM-alignment lessons to review them; nothing is promoted into a skill without your confirmation.
